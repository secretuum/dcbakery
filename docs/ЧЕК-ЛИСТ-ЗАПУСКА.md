# Чек-лист запуска DC Bakery

Единый список ручных шагов — код по всем фичам готов и в `main`. Отмечай галочками.
Всё env — на **веб-сервисе** Render (не на кронах!), кроме отдельно оговорённого.

---

## 1. Переменные окружения (Render → web-сервис → Environment)

### Уже должны быть (проверь, что заданы)
- [ ] `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- [ ] `NEXT_PUBLIC_SITE_URL` = `https://dc-bakery.kz`
- [ ] `PAYMENT_MODE` = `manual`  ← **важно: НЕ `demo`, иначе документы с плашкой «ДЕМО»**

### Telegram-бот
- [ ] `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_GROUP_CHAT_ID`
- [ ] `TELEGRAM_ADMIN_IDS` (твой id)
- [ ] `TELEGRAM_MANAGER_IDS` (id менеджеров, через запятую)
- [ ] `TELEGRAM_ACCOUNTANT_IDS` (id бухгалтера)
- [ ] `CRON_SECRET` (для крона просрочки)
- [ ] `CONSIGNMENT_DAYS` = `4` *(необязательно, дефолт 4)*

### Реквизиты для счёта/накладной (без них документ не выдаётся)
- [ ] `DC_LEGAL_NAME`, `DC_LEGAL_BIN`, `DC_LEGAL_ADDRESS`
- [ ] `DC_BANK_NAME`, `DC_BANK_BIC`, `DC_BANK_IBAN`
- [ ] `DC_BANK_IBAN_PF` (2-й IBAN «Цех ПФ» — для разделения счёта по цехам)
- [ ] `DC_DIRECTOR_NAME`, `DC_TAX_NOTE` (напр. «Без НДС…»)
- [ ] `DC_KBE`, `DC_KNP` *(если бухгалтер дал)*
- [ ] `DC_SUPPLY_RESPONSIBLE`, `DC_CHIEF_ACCOUNTANT` *(ФИО для подписей, необязательно)*
- [ ] `DC_INVOICE_VALID_DAYS` = `5` *(необязательно)*

### WhatsApp клиенту (рассылка счёта)
- [ ] `GREEN_API_INSTANCE_ID`, `GREEN_API_TOKEN` (инстанс авторизован по QR)
- [ ] `WHATSAPP_CLIENT_NOTIFY` = `true`
- [ ] `WHATSAPP_ENABLED` = `false` (остальной WhatsApp спит)

## 2. SQL в Supabase (SQL Editor → выполнить)
- [ ] Таблица `bot_audit_log` (журнал действий бота)

Оба SQL — в `docs/ЗАПУСК-TELEGRAM-БОТА.md`, раздел A.

## 3. Кроны на Render (New → Cron Job)
- [ ] **Просрочка** (ежедневно `0 3 * * *`): `curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://dc-bakery.kz/api/cron/overdue` + env `CRON_SECRET` на этом кроне
- [ ] **Описания** (месячно `0 3 1 * *`): `node scripts/cron-refresh-descriptions.mjs` + env `OPENAI_API_KEY`/`IIKO_*`/`SUPABASE_*` на этом кроне

## 5. Онбординг бота
- [ ] Бот добавлен в общий групповой чат (id группы отрицательный = `TELEGRAM_GROUP_CHAT_ID`)
- [ ] Бухгалтер нажала `/start` боту в личке (иначе ЛС с реквизитами не откроется)
- [ ] id менеджеров/бухгалтера внесены в env и сделан рестарт

---

## 6. Тесты (после всего выше)
- [ ] **Бот e2e:** заявка → «Подтвердить» → карточка в чат меняется на «Ждёт оплаты», бухгалтеру в ЛС падают реквизиты → «Оплачено» → карточка на «Оплачен» + «В работу»; строки в `bot_audit_log`
- [ ] **WhatsApp клиенту:** оформить заказ со своим номером → подтвердить → пришло сообщение со счётом
- [ ] **Документы:** у подтверждённого заказа открыть счёт/накладную → нет «ДЕМО», реквизиты боевые, печать = только документ (с заголовком и подписями)
- [ ] **Валидация:** регистрация с кривым БИН/номером → ошибка; номер без WhatsApp → отклонён
- [ ] **Карточка товара** на kk/en: фасовка/срок/хранение переведены

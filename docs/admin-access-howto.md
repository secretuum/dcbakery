# Как заводить сотрудников и выставлять доступы (админ / торгпред)

## Модель доступа (3 уровня)
| Кто | Что может | Как назначается |
|---|---|---|
| **Админ** (full) | Всё: заказы, подтверждение/оплаты, товары/цены, настройки, клиенты | `app_metadata.role="admin"` ИЛИ email в `ADMIN_EMAILS` |
| **Торгпред** (manager) | Видит всё; заводит клиента и заявку; **но не принимает оплаты, не меняет цены/настройки, не подтверждает заказы** | `app_metadata.role="manager"` ИЛИ email в `MANAGER_EMAILS` |
| **Суперадмин** (правка сайта) | Full-админ + редактирование контента сайта | full-админ, чей email в `SUPERADMIN_EMAILS` |

Вход всем — `/admin/login`, по **email + паролю** (Supabase).

---

## Шаг 1 — создать человеку логин (Supabase)
Для КАЖДОГО сотрудника (и админа, и торгпреда):
1. Supabase Dashboard → проект → **Authentication** → **Users** → **Add user** → **Create new user**.
2. Введи **email** и **пароль**, отметь **✔ Auto Confirm User** (иначе попросит подтверждение по почте).
3. Create. Готово — это его вход.

## Шаг 2 — выдать роль (выбери ОДИН способ)

### Способ А — через env на Render (проще, без SQL; нужен редеплой)
Render → твой сервис → **Environment** → задай/дополни (email через запятую):
```
ADMIN_EMAILS=ты@x.kz,второй-админ@x.kz
MANAGER_EMAILS=торгпред1@x.kz,торгпред2@x.kz
SUPERADMIN_EMAILS=ты@x.kz
```
Save → сервис передеплоится сам. Роль применится по email при логине.

### Способ Б — через app_metadata (без редеплоя; персонально)
Supabase → **SQL Editor** → выполни (роль `manager` или `admin`):
```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"manager"}'::jsonb
where email = 'торгпред@x.kz';
```
Действует со следующего логина.

> ⚠️ Роль строго в **`app_metadata`** (raw_app_meta_data), НЕ в `user_metadata` — иначе пользователь сможет выписать её себе сам.

## Шаг 3 — правка сайта (суперадмин)
`SUPERADMIN_EMAILS` — **только твой email** (и доверенных). Полный админ БЕЗ этого списка работает в админке, но **сайт редактировать не может**. Торгпред — тем более (правку сайта не получает никогда).

---

## Проверка
- **Админ:** зашёл в `/admin` → делает всё (подтверждает заказ, меняет цену) без ошибки.
- **Торгпред:** зашёл → в шапке бейдж «менеджер · только просмотр»; видит клиентов/заказы/цены; при попытке подтвердить заказ / отметить оплату / сменить цену → **403 «Недостаточно прав»**. Это правильно.

## Частые вопросы
- **Торгпред не может принять заявку** — так и задумано: заявку принимает/подтверждает только админ.
- **Новый админ не видит карандаши правки сайта** — добавь его email в `SUPERADMIN_EMAILS` (если ему это нужно).
- **Один email в двух списках** — победит `admin` (проверяется первым).
- **Пароли** — каждому свой личный, не общий.

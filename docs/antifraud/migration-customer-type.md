# Миграция: колонка `orders.customer_type` (Связка 3)

**Кто применяет:** владелец (я миграции не запускаю — правило `CLAUDE.md`).
**Когда:** до/после мержа ветки `antifraud-bin-check` — код деплой-безопасен (см. ниже),
но **пока миграция не применена, тип клиента не сохраняется** (заказы создаются штатно).

## SQL

```sql
-- Тип B2B-клиента, заявленный при оформлении: юрлицо / ИП / физлицо.
-- Nullable — старые заказы остаются NULL, ничего не ломается.
alter table public.orders
  add column if not exists customer_type text
  check (customer_type is null or customer_type in ('legal', 'ip', 'individual'));

comment on column public.orders.customer_type is
  'Самоназванный тип клиента: legal=юрлицо, ip=ИП, individual=физлицо (самозанятый). NULL у старых/бот-заказов.';
```

Прогнать в Supabase SQL Editor, либо оформить файлом `supabase/migrations/<ts>_add_customer_type.sql`
и `supabase db push` (по вашему обычному процессу).

## Почему деплой-безопасно (порядок не критичен)

- Основная вставка заказа (`insertOrderWithItems`) **НЕ трогает** `customer_type` —
  колонка пишется **отдельным best-effort апдейтом** (`updateOrderCustomerType`,
  как `telegram_message_id`). Нет колонки → апдейт тихо падает в `.catch()`, заказ уже
  сохранён. Есть колонка → заполняется штатно.
- Серверная валидация «БИН обязателен для юрлица/ИП» (`order-validation.ts`) от колонки
  НЕ зависит — работает сразу после деплоя кода.

Итог: можно мержить код и применять миграцию в любом порядке; для фактического
сохранения типа — применить миграцию.

## Что уже в коде ветки (Связка 3)

- `CustomerType` в `src/types`; поле `Order.customer_type?`.
- `CheckoutForm`: селектор «Юрлицо / ИП / Физлицо», БИН обязателен для юрлица/ИП
  (клиентская валидация), скрыт у физлица, хинт «БИН проверяется автоматически».
- `order-validation.ts`: серверное правило required-БИН для legal/ip (+тесты) — НЕ обходится.
- `/api/orders`: приём `customer_type`, валидация, best-effort сохранение.
- Админ-карточка заказа: строка «Тип клиента» + блок вердикта по БИН (Связка 2).

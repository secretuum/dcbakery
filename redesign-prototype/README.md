# DC Bakery — прототип полного редизайна

Статический дизайн-прототип сайта DC Bakery: чистый HTML, CSS и JavaScript, без сборки, без backend, без внешних сервисов.

Прототип **не трогает production-код сайта** — он лежит отдельной папкой `redesign-prototype/` внутри репозитория и ни на что не влияет.

---

## Как запустить

Способ 1 — просто открыть файл:

```bash
start redesign-prototype/index.html
```

Способ 2 — локальный сервер (рекомендуется: корректные относительные пути и hash-маршруты):

```bash
npx serve redesign-prototype -l 4321
```

Затем открыть `http://localhost:4321/`.

UI-kit:

```bash
start redesign-prototype/ui-kit.html
```

или ссылка «UI-kit прототипа» в подвале и кнопка **«Открыть UI-kit →»** в инспекторе состояний.

---

## Инспектор состояний

Ключевой инструмент просмотра. Кнопка **«Состояния»** у правого края экрана (на мобильном — круглая кнопка справа).

Панель даёт:

- переход на **любой из 16 экранов**;
- переключение **всех состояний текущего экрана** (skeleton, empty, error, success, loading, варианты наличия и т. д.);
- открытие **каждого оверлея** (меню, фильтры, карточка товара, корзина, подтверждение удаления, ошибка, успех, tooltip, dropdown, toast, платёжный шлюз);
- готовые наборы корзины (пустая, ниже минимума, минимум достигнут, предупреждение об остатке).

Ни один слой дизайна не существует только в коде — всё открывается кнопкой.

## Состояния

### Главная
- прогресс акции 0 % / 65 % / награда получена;
- раскрытая панель условий акции;
- информационный tooltip акции;
- корзина без товаров / с индикатором количества;
- шапка обычная / sticky (появляется при прокрутке).

### Каталог
- обычная загрузка, skeleton, пустой результат поиска, ошибка загрузки;
- активные фильтры (чипы со сбросом), фильтры открыты на mobile;
- товар в наличии / мало (осталось N) / нет в наличии;
- товар без изображения (нейтральная заглушка с названием);
- товар добавлен в корзину (подтверждение на карточке);
- stepper количества, быстрая кнопка добавления, «Показать ещё».

### Карточка товара
- обычное, loading, ошибка получения данных;
- нет в наличии, количество 1, количество несколько;
- desktop — крупное модальное окно (фото + данные + закреплённая панель покупки);
- mobile — полноэкранная фотография, кнопка назад, chips, раскрывающийся состав, полупрозрачная нижняя панель.

### Корзина
- компактный индикатор в шапке и в нижней навигации;
- desktop drawer, мобильная bottom sheet, отдельная страница;
- пустая, ниже минимальной суммы, минимум достигнут;
- изменение количества, удаление позиции с подтверждением;
- предупреждение об остатке;
- loading, ошибка;
- sticky-панель с итогом и прогресс до 15 000 ₸.

### Оформление
- пустая форма, заполненная форма (кнопка «Заполнить демо-данными»);
- ошибки валидации по каждому полю;
- выбор даты доставки, недоступные даты (только вт · чт · сб);
- loading отправки, ошибка backend;
- заявка создана + ожидание подтверждения менеджером.

### Авторизация и профиль
- вход: форма, loading, ошибка входа, отдельный менеджерский вход;
- регистрация: анкета → код из WhatsApp → неверный код → аккаунт создан;
- восстановление пароля: форма → письмо отправлено;
- профиль: карточка клиента, товарный кредит, реквизиты, адреса, быстрый повтор, история заказов, выход;
- заказы: список, loading, пусто, фильтры по статусу;
- детали заказа: 5 статусов (в производстве, ожидает оплаты, отгружен, завершён, отменён).

## Адаптивность

Проверено на **390 × 844**, **768 × 1024**, **1440 × 900** — все 16 экранов и все 54 состояния:

- горизонтального переполнения нет ни на одной ширине;
- ошибок в консоли нет;
- desktop — отдельная раскладка (сайдбар фильтров, 4 колонки, side sheet корзины, модальная карточка товара);
- mobile — своя раскладка (нижняя навигация, горизонтальные карусели, bottom sheets, полноэкранная карточка товара, плавающая мини-корзина).

## Что является заглушкой

Прототип **ничего не отправляет и никуда не ходит**. Демонстрационные действия:

| Действие | Что происходит |
|---|---|
| «Отправить заявку» | локальная валидация → спроектированный экран loading → success-screen |
| «Войти» | открывает демонстрационный профиль Coffee Point |
| «Получить код в WhatsApp» | показывает экран ввода кода, код не отправляется |
| «Оплатить картой» | заглушка «Здесь будет переход к платёжной системе» |
| «Счёт PDF» / «Накладная PDF» | toast-заглушка |
| Переключение языка | визуальная демонстрация, тексты не переводятся |
| «Повторить заказ» | локально переносит позиции демо-заказа в корзину |
| «Заказать в розницу» | `href="#"` + toast, см. ниже |

Заглушки помечены в интерфейсе плашкой с пунктирной рамкой (`.stub`) и комментариями `TODO(backend)` в коде.

## Что нужно будет подключить к backend

1. **Каталог и остатки** — `data.js` → реальный источник (Supabase / 1С). Поля совпадают с production-моделью: `slug, name, category, subcategory, description, composition, compositionKz, weightLabel, weightGrams, unit, price, stock, storage, shelfLife, packageType, isHalal, image`.
2. **Корзина** — сейчас в памяти страницы, без хранения между сессиями.
3. **Оформление заявки** — `POST /api/orders`, валидация на сервере, уведомление менеджера.
4. **Авторизация** — вход, регистрация, OTP в WhatsApp, восстановление пароля, сессия клиента.
5. **Кабинет** — реквизиты, адреса доставки, товарный кредит, история заказов, документы (счёт, накладная, АВР).
6. **Оплата** — платёжный шлюз банка-эквайера и статусы оплаты.
7. **Прогресс акции** — расчёт суммы заказов недели по БИН/ИИН.
8. **Локализация** — RU / KK / EN (в production по умолчанию **казахский**, см. «Открытые вопросы»).
9. **Ссылка «Заказать в розницу»** — реальный URL del Cappuccino.

## Открытые вопросы

1. **Язык по умолчанию.** В production `DEFAULT_LOCALE = "kk"` (казахский) — русские строки в коде являются ключами словаря. Прототип сделан на русском (как и техническое задание) с переключателем RU / KK / EN. Если основной язык витрины — казахский, тексты и ширины блоков нужно пересчитать: казахские строки длиннее русских на 15–40 %.
2. **URL розничного сайта del Cappuccino.** Реального адреса нет ни в коде (`NEXT_PUBLIC_RETAIL_SITE_URL` не задан, фолбэк `https://example.com`), ни в `.env.local`, ни на живом сайте. Во всех трёх местах кнопки «Заказать в розницу» стоит `href="#"` и комментарий `TODO(backend)`. Адрес не выдуман.
3. **Отдельные страницы входа и регистрации.** На действующем сайте `/login` и `/register` отвечают 404 — авторизация происходит в модальном окне при оформлении заказа и на `/profile`. В прототипе они сделаны отдельными экранами, как указано в задании; тексты и правила валидации взяты из существующего модального окна авторизации.
4. **Банкетные десерты и готовые обеды.** В production скрыты флагами `BANQUET_DESSERTS_ENABLED` и `READY_MEALS_ENABLED`. Банкетные десерты в прототипе показаны как отдельная категория (данные реальные), готовые обеды не показаны.

## Замечания по коду

- Код не минифицирован, все секции размечены комментариями.
- Внешних зависимостей нет. Шрифты подключаются с Google Fonts одной строкой `@import` — при отсутствии сети работают системные фолбэки, вёрстка не ломается.
- Иконки — инлайновый SVG-спрайт (48 символов), одинаковый в `index.html` и `ui-kit.html`.
- `script.js` — один IIFE без глобальных переменных, кроме `window.DC` из `data.js`.

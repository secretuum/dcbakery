# docs/i18n — комплект для вычитки казахского носителем

Это **не рабочие словари сайта**, а выгрузка для человека: носитель правит казахскую
колонку и возвращает файл, программист разносит правки обратно в словари.
Рабочие словари — `src/i18n/kk.json` и `src/i18n/en.json`, ключ словаря = русская
строка-оригинал. **Источник истины — они.** Выгрузка делается из них и никогда наоборот:
правка, внесённая только сюда, на сайт не попадёт.

## Что в папке

| Файл | Что это |
|---|---|
| `strings-translated.md` | **То, что отдают носителю.** Таблица «Ключ / Русский / Қазақша / English / Статус», казахская и английская колонки заполнены текущим переводом |
| `strings-source.md` | Та же таблица с пустыми переводами — если нужен перевод с нуля |
| `ru.json`, `kk.json`, `en.json` | Тот же комплект машиночитаемо: S-ключ → текст. По ним удобно сверять, что вернул носитель |
| `previous-export.json` | Снимок прошлой выгрузки: какие строки носителю уже отправляли. Из него берётся колонка «Статус» |
| `excluded.json` | Строки, которые в словарях ещё лежат, но на сайте отменены — в выгрузку не попадают, с причиной по каждой. Когда строку удалили из словарей, запись переносят из `strings` в `cleared` с коммитом удаления, а не стирают |
| `kk-oferta-proposed.md` | Отдельная история: правки казахской оферты от 06.08.2026, ждут подтверждения носителя и юриста |

S-ключи (`S001`, `S002`, …) — нумерация **внутри одной выгрузки**, при пересборке она
меняется. Связывать разные выгрузки по S-ключу нельзя, общий идентификатор строки —
русский текст.

## Как пересобрать

```bash
node scripts/i18n-export.mjs
```

Скрипт читает `src/i18n/*.json`, раскладывает строки по разделам (определяя по коду,
где строка показывается), и перезаписывает пять файлов комплекта. Флаги:

- `--date=19.09.2026` — дата в шапке файлов (по умолчанию сегодняшняя);
- `--new-since=2026-09-18` — строки, добавленные в словарь начиная с этой даты,
  помечаются в колонке «Статус» как новые (дата по умолчанию — `highlight_since`
  из `previous-export.json`);
- `--why` — печатает, из какого файла и строки кода выведен раздел каждой строки;
  нужен, когда строка уехала не в тот раздел и надо поправить правила в скрипте.

Пересобирать нужно **после каждой правки `src/i18n/*.json`** — иначе носителю уедут
строки, которых на сайте уже нет. Ровно это и случилось к 19.09.2026: комплект был
собран 17.07.2026 вручную, за два месяца из него умерла 51 строка (отменённые тарифы
доставки 1 500–3 000 ₸, «минимального заказа нет», старые редакции пунктов 5.5 и 7.2
оферты), а 262 живые строки в него не попали вовсе.

## Что попадает в выгрузку

- все ключи из `src/i18n/kk.json` и `src/i18n/en.json` (ключ = русский оригинал);
- **минус** строки из `excluded.json` — отменённые условия, которые из словарей ещё не
  удалили;
- **плюс** строки, которые вызываются в коде через `t("…")`, но в словарях их нет: на
  казахской версии сайта они показываются по-русски. У них пустая колонка «Қазақша» и
  статус «НЕТ В СЛОВАРЕ». Когда носитель их переведёт, программист заводит под них
  новые ключи в словарях.

Односторонние пропуски (с 21.09.2026, правило в `src/i18n/export-status.ts`, тест рядом):

- строка есть в `en.json`, но нет в `kk.json` — громкий статус «НЕТ КАЗАХСКОГО ПЕРЕВОДА»:
  казахская версия показывает её по-русски, а это работа носителя;
- строка есть в `kk.json`, но нет в `en.json` — статус не меняется, в колонке «English»
  тихая отметка «_нет в en.json_».

До 21.09.2026 помечалось только отсутствие в обоих словарях, и «кг» (есть в en, нет в kk)
ушла бы носителю пустой клеткой без предупреждения.

Сборка 19.09.2026: 890 ключей в словарях − 10 отменённых + 3 строки из кода без
перевода = **883 строки** в комплекте (было 662 от 17.07.2026).

Сборка 21.09.2026: 884 ключа, отменённых в словарях больше нет (все 10 записей
`excluded.json` удалены из словарей в 3d209a8 и перенесены в `cleared`) = **884 строки**.
Добавилась «Из этого же раздела» (PR #45). Пропуски: «кг» — нет казахского; шесть строк
(«Пекарня полного цикла», «Собственное производство», «...», «…», «DC Bakery — B2B
поставщик в Алматы», «Мы специализируемся на поставках…») — нет английского.

Сборка 21.09.2026 (вторая): 898 ключей, отменённых нет, строк из кода без перевода нет =
**898 строк** (+14). Прибавка — тексты разделов каталога (PR #49): по заголовку и
описанию у десертов, полуфабрикатов и мяса (6), значения фактов («у всех позиций
раздела», «коробка или банка», «+2…+8 °C», «от 72 часов до 10 суток…», «−18 °C»,
«6 месяцев», сроки для мяса — 7) и подпись «Коротко о разделе» (1). У всех 14 есть kk и
en, статус «НОВОЕ с 18.09.2026». Заголовок каталога «Каталог оптом, Алматы — десерты,
полуфабрикаты» в kk и en теперь про полуфабрикаты, а не мясо (fe2cef1). Пропуски те же:
«кг» — нет казахского, шесть строк — нет английского. Новые строки встали в середину
списка, поэтому S-номера с S116 сдвинулись — сверять возврат носителя только с этой
выгрузкой.

## Как идёт вычитка

1. Пересобрать комплект и отдать владельцу `strings-translated.md`.
2. Носитель правит **только колонку «Қазақша»**, колонки «Ключ» и «Русский» не трогает,
   возвращает файл целиком. Колонка «Статус» подсказывает, с чего начинать:
   помеченные как новые строки никто не проверял, это машинный перевод.
3. Программист разносит правки: для каждой изменённой строки берёт из таблицы русский
   текст — это ключ в `src/i18n/kk.json` — и кладёт туда новое значение.
   Быстрая сверка, что вернулось: собрать из возвращённого файла `kk.json` по S-ключам
   и сравнить с `docs/i18n/kk.json` этой выгрузки.
4. После того как правки в словарях: обновить `previous-export.json` — положить в
   `strings` значения свежего `docs/i18n/ru.json` и сдвинуть `highlight_since` на дату
   следующей волны правок. Тогда в следующий раз статусы снова будут честными.
5. Пересобрать комплект — он станет отражением словарей уже с правками носителя.

## Чего здесь нет

- **Названия, описания и составы товаров** — они лежат в базе (`catalog_product_overrides`),
  не в словарях. Их выгружают и заливают отдельно, заливка — `scripts/apply-kk-translations.mjs`.
- **Строки админки** почти целиком: менеджеры работают на русском, в словарях от админки
  осталось несколько случайных строк.

## Ограничения скрипта

Раздел для строки определяется поиском её текста по `.ts`/`.tsx` в `app/` и `src/`.
Строка, которая собирается в коде из кусков или приходит из настроек сайта, по коду не
находится — такие собраны в последнем разделе «Строки, место которых в коде не
определено». Это влияет только на раскладку по разделам: в выгрузку строка попадает в
любом случае, пока она есть в словаре и не указана в `excluded.json`.
